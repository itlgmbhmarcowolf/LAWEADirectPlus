## Geklärte Entscheidungen

### Externer Deploy-Blocker vom 05.10.2026

Der statische Kundengespräch-Build wurde lokal erstellt und geprüft. Commit `2cadd91` mit dem Vorschau-Einstiegspunkt und der Vercel-Konfiguration wurde erfolgreich nach `origin/main` (`itlgmbhmarcowolf/LAWEADirectPlus`) gepusht. Eine Vercel-URL konnte aus dieser Umgebung noch nicht erstellt werden: Der Vercel-App-Connector verlangt erneute Authentifizierung; der alternative Deploy-Endpunkt war aus dem Terminal auch mit erweitertem Netzwerkzugriff nicht erreichbar. Im Vercel-Git-Import wird das Repository laut Nutzer-Screenshot nicht angezeigt. Nächster externer Schritt: Im Git-Import nach `LAWEADirectPlus` suchen und, falls es fehlt, den Repository-Zugriff der Vercel-GitHub-App für dieses Repository freigeben. Danach `frontend` als Root Directory importieren. Für einen einmaligen öffentlichen Konzeptlink kann stattdessen der bereits gebaute Ordner `frontend/dist/` über Vercel Drop hochgeladen werden. Das ist nur für die fiktive Vorschau geeignet; kein produktiver Portalbetrieb.

**Ergänzung:** Für das Kundengespräch wurde auf direkte Nutzerentscheidung eine simulierte Anmeldeseite vor die öffentliche Konzeptvorschau gesetzt. E-Mail-Adressen, Passwort und OTP sind ausdrücklich fiktiv und dienen nur der Navigation; diese Oberfläche ist kein Authentifizierungssystem. Das separate Backend-Projekt auf Vercel wird von diesem statischen Frontend nicht kontaktiert.

## Vorgehen bei einer Entscheidung

Für jede Entscheidung Datum, fachlichen Owner, bestätigten Wert, betroffene Regeln/Schnittstellen, Migrationsbedarf und Abnahmetest ergänzen. Ändert die Entscheidung eine hier beschriebene vorläufige Regel, zuerst `03-fachliche-anforderungen.md` und die Tests aktualisieren, dann implementieren. Blockierende Punkte dürfen in einer Demo sichtbar offen sein; sie dürfen nicht im produktiven Ablauf durch plausible Fantasiedaten ersetzt werden.
